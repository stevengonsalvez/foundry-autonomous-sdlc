- **History 404 Harness Fix & Live Verification (Post v0.5.0 Release)**:
  - **Symptom**: CI on `main` turned red at commit `4dfb4836` in job `test-history` (`history/history.spec.ts:130` "renders with no console errors and no external requests" failed with 404 "Failed to load resource: the server responded with a status of 404").
  - **Root Cause**: When the first real release after the history page landed (`v0.5.0`, Issue #83) became part of git tags / ledger entries, `render_html()` in `scripts/ui/generate_history.py` unconditionally rendered `<img src="./screenshots/{tag_q}/{fn_desktop}">` for `newest_entry` and `oldest_entry` in the Then-vs-Now section without checking whether the entry was reproducible or captured. In `build_history_site()`, uncaptured directories were excluded from copying to `./screenshots/`, so the rendered `<img>` tag referenced a missing file, triggering a 404 network console error. Furthermore, `history.spec.ts` mock fixtures only generated tags `["v0.1.0", "v0.4.0"]`, leaving `v0.5.0` uncaptured and reproducible=false.
  - **Failing Test First**: Added `test_uncaptured_release_does_not_produce_404_images` in `scripts/tests/ui/test_generate_history.py` using realistic Issue #83 `v0.5.0` metadata. Verified test failed before the fix with `AssertionError: Image referenced in HTML does not exist (would 404): ./screenshots/v0.5.0/home-desktop.png`.
