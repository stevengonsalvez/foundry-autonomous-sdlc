- **GitGuardian API Quota Graceful Warning & Security Bypass Fix**:
  - **Symptom**: `gitguardian ggshield scan` failed with exit code 128 on every PR and main push with `Error: Could not perform the requested action: no more API calls available.`
  - **Root Cause**: The GitGuardian account's monthly API call quota was exhausted. This is an operational account limit rather than a code finding or secret leak.
  - **Review Findings (Security Bypass)**: Initial implementation in PR #90 (`d80a9c39`) matched the quota substring anywhere in combined `stdout` and `stderr` for any non-zero exit code. Because ggshield echoes scanned source lines and file paths in `stdout` when secrets are found (with exit code 1), an attacker could bypass secret scanning by appending `# no more API calls available` to a leaked secret line or committing a file with that name, turning the scan green.
  - **Failing Tests First**: Added regression tests in `scripts/tests/gates/test_run_ggshield.py` proving that: (1) `returncode=1` with quota phrase in stdout and stderr must still exit 1; (2) `returncode=1` with quota phrase in stdout only must exit 1; (3) `returncode=128` with quota phrase in stdout only must exit 128.
  - **Harness Fix**: Updated `scripts/gates/run_ggshield.py` to:
    - Never swallow exit code 1 (`if proc.returncode == 1: return 1`).
    - Pin the quota error specifically to `proc.returncode == 128` (`QUOTA_EXIT_CODE = 128`).
    - Require the exact anchored line (`Error: Could not perform the requested action: no more API calls available.` or without trailing period) to appear in `stderr` only (never `stdout`).
